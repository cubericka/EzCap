# EzCap 설치·업데이트·데이터 안내

공식 내부 버전은 1.0.0, 설치 파일명은 `EzCap 1.0.exe`입니다. GitHub 첨부 파일은 공백이 점으로 치환된 `EzCap.1.0.exe`로 내려받습니다. 해시 확인 후 파일명을 **`EzCap 1.0.exe`**로 바꾸고 실행하세요. 파일 내용은 바뀌지 않습니다.

## 설치 위치와 권한

현재 사용자 설치(HKCU)를 유지합니다. 기존 설치 등록이 있으면 해당 위치를 제안하고, 신규 설치의 기본 제안은 `C:\EzCut`입니다. **내 사용자 폴더**를 선택하면 `%LOCALAPPDATA%\Programs\EzCut`을 사용합니다. 쓰기 권한이 있는 폴더만 선택하세요. 다른 파일을 함께 보관하기보다 전용 하위 폴더를 권합니다.

한글·공백 경로는 기존 방식대로 처리합니다. 이번 파일의 Windows 실제 설치와 다양한 경로·권한 조합은 아직 실행 검증하지 않았습니다.

## 업데이트와 복구

새 EXE를 실행해 기존 경로에 설치하세요. 실행 중인 앱에는 정상 종료를 요청하고 종료를 확인합니다. 설치 실패 시 기존 파일·등록 정보를 복원하는 구조와 이전 버전 복구 버튼을 유지합니다.

이름 변경 이전의 1.7.x와 EzCap 1.0.0은 버전 표기 체계가 다릅니다. 기존 등록 식별자를 유지하며 버전 숫자만으로 다른 제품으로 취급하지 않습니다. 이전 실행 파일로 되돌리려면 현재 설치창의 **이전 버전 복구**를 사용하세요. 이전 이름의 오래된 설치 EXE로 새 EzCap 실행 파일을 직접 덮어쓰는 것은 지원 확인을 하지 않았습니다.

바로가기는 EzCap으로 표시됩니다. 호환성을 위해 설치 폴더의 실제 실행 파일명 `ClearCapture.exe`, 제거 작업 파일명, 레지스트리 내부 식별자를 유지합니다. EXE 제품 정보와 화면 이름은 EzCap입니다. 이 내부 파일들을 수동으로 바꾸지 마세요.

## 사용자 데이터

| 용도 | 현재 기본 위치 |
| --- | --- |
| 이미지 저장 | Windows 사진 폴더\EzCut |
| 설정·데이터 | %LOCALAPPDATA%\EzCut\Data |
| 복구 데이터 | %LOCALAPPDATA%\EzCut\RecoveryData |
| 임시 복구 데이터 | %TEMP%\EzCut-사용자명\RecoveryData |
| 새 진단 로그 | %LOCALAPPDATA%\EzCut\Maintenance\Logs |
| 제거 임시 작업 | %LOCALAPPDATA%\EzCut\Maintenance\Jobs |

이전 사진/ClearCapture 기본 경로는 설정을 읽을 때 한 번 사진/EzCut으로 전환합니다. 사용자가 직접 지정한 저장 경로는 유지하며 기존 사진·GIF 파일은 이동하거나 삭제하지 않습니다. 전환 저장 후 사용자가 다시 선택한 경로도 유지합니다.

이전 ClearCapture 데이터·복구 폴더는 새 EzCut 위치로 복사하고 검증한 뒤 내부 메타데이터 경로를 바꿉니다. 이전 원본은 복구용으로 보존합니다. 새 위치에 자료가 있으면 덮어쓰거나 자동 병합하지 않습니다. 임의로 이전 폴더를 지우지 마세요. 이전 로그는 기존 위치에 남으며 새 로그부터 새 폴더를 사용합니다.

제거 시 설정·캐시 삭제 선택과 관계없이 개인 캡처 원본·보관 편집·외부 저장 이미지·GIF는 보존 대상으로 처리합니다. 일반 종료 시 최근 목록·캐시 정리 기본 동작은 유지합니다. 이 두 동작은 별개입니다. 오류가 발생하면 오류창의 진단 로그 경로를 확인하세요.

2026-11-20 기준 이번 빌드의 Windows 실제 저장·데이터 이관·제거 동작 확인은 미실시입니다.

## SHA-256 확인

파일명을 바꾸기 전에 PowerShell에서 다운로드한 폴더로 이동한 뒤 실행합니다.

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\EzCap.1.0.exe'
```

표시된 Hash를 같은 Release의 `SHA256SUMS.txt`와 비교하세요. 다르면 실행하지 말고 공식 배포처에서 다시 받으세요. 해시 계산 후 파일을 수정하거나 서명하면 해시가 바뀌므로 다시 검증해야 합니다.
